# Reader 0.9.0 (fixes for your reports, faster screen reader mode)

Released 8 November 2026 for Android phones and Windows PCs.

This version answers the five problems and requests testers reported earlier today (#1 to #5). Each one is listed below with what we changed. **Please check each one and tell us whether it is fixed for you.**

## Get the app

Both files are in the Saksham OneDrive folder **Reader tester builds / 0.9.0**.

| Device | File | Needs |
|---|---|---|
| Android phone | `Reader-0.9.0.apk` (55 MB, build 20) | Android 7 or later |
| Windows PC | `Reader-Setup-0.9.0.exe` (116 MB) | Windows 10 or 11, 64-bit |

Both install over 0.8.0 or any earlier tester build and keep your books and saved places. `SHA256.txt` in the same folder lets you check the files arrived intact.

To see which version you have: on Windows, **Help → About Reader**; on Android, the **Help** screen.

## Your reports and what we did

### #1 NVDA sentenceNav: next/previous sentence read from the wrong place and left the text (Windows)

[Issue #1](https://github.com/anubhav9001/accessible-reader/issues/1)

- Alt+Down and Alt+Up are now left to your screen reader in the book's text box, so sentenceNav gets them. Use **H** and **Shift+H** there to move by heading.
- The book text is now one native Windows text box holding the whole book (see #3), so there is no edge of the text for sentenceNav to fall off, and focus no longer jumps to the menus or toolbar.

**Please check:** with sentenceNav, move by paragraph, then by sentence. Does sentence navigation start from the cursor, and carry on through the whole book?

### #2 Narrator: next/previous sentence skipped text (Windows)

[Issue #2](https://github.com/anubhav9001/accessible-reader/issues/2)

- Narrator's own sentence command skips text in many Windows text boxes, not just Reader's, and we cannot change how Narrator moves. Reader now has its own sentence keys that work with any screen reader: **full stop** reads the next sentence and **Shift+full stop** the previous one, and the cursor moves with them.

**Please check:** with Narrator, does full stop / Shift+full stop move one sentence at a time without skipping? Does Narrator's own sentence command behave better now than in 0.8.0?

### #3 Narrator responded slowly (Windows)

[Issue #3](https://github.com/anubhav9001/accessible-reader/issues/3)

- **Screen reader mode now uses a native Windows text box** instead of a web page text box. Narrator was waiting up to 1.4 seconds for answers from the old box; the new one answers in a few milliseconds. It holds the whole book, so Narrator's read-all and NVDA's say all go on to the end.
- Reader no longer updates the page (heading, page and time) while you are pressing the arrow keys, only once you stop. That was flooding screen readers with change messages and made Narrator fall behind the cursor.
- If the new box causes a problem, you can go back to the old one: **Settings → Screen reader → Use the Windows text box**, turn it off.
- Getting the new box to work well with NVDA and Narrator also needed these fixes:
  - Ctrl+T, Tab and the menus now really move the keyboard out of the book text, and back again when you return. Before, the arrow keys sometimes kept moving the book's cursor after you had left.
  - The jump keys (**H**, **K**, **L**, **T**, the number keys and so on) now say where you landed with both NVDA and Narrator. In the first version of the new box they were silent.
  - Escape in the table of contents goes back to the book text.

**Please check:** with Narrator, is moving by line, paragraph and word now about as quick as in Microsoft Word? Do the jump keys speak? Does Narrator stay with the cursor when you press the arrow keys quickly?

### #4 Next heading and Next section seemed to do the same thing (Windows and Android)

[Issue #4](https://github.com/anubhav9001/accessible-reader/issues/4)

- **Next section** (Ctrl+Page Down on Windows) now skips sub-sections: it goes to the next entry of the contents at the same level or higher, for example chapter to chapter. **Next heading** (Alt+Down, or H in screen reader mode) still stops at every heading down to your heading depth.
- The guides and keyboard shortcut list explain the difference.

**Please check:** in a book with chapters and sub-sections, do the two commands now feel clearly different, and is that the difference you wanted?

### #5 Open the last book read when the app starts (Windows and Android)

[Issue #5](https://github.com/anubhav9001/accessible-reader/issues/5)

- New setting: **Open the last book read when Reader starts** (Windows) / **Open the last book when the app starts** (Android). With it on, Reader skips My books and opens your last book at your place.

**Please check:** turn it on, close Reader, open it again. Does it open the right book at the right place?

## Also changed since 0.8.0

### On both

- **App log for problem reports.** Tester builds keep a log of what the app did: what you opened, the commands you used, what it said to your screen reader, and any errors. It never contains the book's text or full file paths. Please attach it when you report a problem: on Windows **Help → Open log folder** (send `reader.log`); on Android **Help → Copy the app log**, then paste it. The problem report form asks for it.

### On Windows

- **Tables in their own window** (press Enter on a table in screen reader mode) are now read cell by cell with the arrow keys, without changing your screen reader's mode. Each cell says its column heading and row heading, including tables whose heading row is not marked as one in the book. NVDA's table commands (Ctrl+Alt+arrow keys) work too. Escape always closes the window and returns you to the same place in the text, even after you have tabbed to the Close button.
- **Dialog titles are read when a dialog opens.** Settings, My books, Reading commands, Go to page and Online libraries now say their name when they open. Narrator used to say nothing.
- Tab from the book text goes to the next control, no longer to the hidden "Skip to book text" link.

### On Android

- The **Open the last book** setting (#5), the clearer **Next section** (#4) and the app log, as described above.

## Known limits

- **Narrator** (Windows): we tested Narrator's fixes with Windows' own testing tools, not by listening. Some messages may be read twice, or a word or two late. Please tell us exactly what you hear.
- **JAWS** (Windows): not yet tested with this version. Reports from JAWS users are especially welcome.
- **NVDA** (Windows): coming back to the book text from the contents or a dialog, NVDA may first read the surrounding area and a heading before "Book text". Entering the table of contents it says "contents".
- **Narrator's own sentence command** (Windows) may still skip text; use full stop and Shift+full stop instead (#2).
- **Open book** (Ctrl+O, Windows) is the standard Windows Open window. If your screen reader doesn't read its title, tell us which one you use.
- Reading aloud stops when the phone screen locks or you leave the app (Android).
- Sugamya Pustakalaya downloads inside the app are still coming. Download the book on the website, then add it with **Add book** (Android) or **Open book** (Windows).
